# INA3221 battery monitoring

[Deutsch](INA3221.de.md)

The prototype now uses an optional INA3221 firmware package for the ordered black DAOKAI three-channel module. The earlier INA219 package remains an alternative; **use one measurement package only**.

On 2026-10-05 the prototype configuration compiled with ESPHome 2026.9.1 and was installed successfully through encrypted OTA. The ESP reconnected and reported USB power with unknown battery/charging/runtime readings, as expected without the module. Physical INA3221 measurement tests remain pending.

## Firmware

Copy `power-monitoring-ina3221.yaml` and `usb-detection.yaml` beside your device configuration:

```yaml
packages:
  power_monitor: !include power-monitoring-ina3221.yaml
```

The package includes USB detection. Remove any separate `usb_detection` package or inline copy of its entities before adding it. For the existing German firmware, use the same ID overrides as the INA219 package:

```yaml
packages:
  power_monitor: !include
    file: power-monitoring-ina3221.yaml
    vars:
      pm_battery_script: akku_verarbeiten
      pm_voltage_id: akkuspannung_echt
      pm_warning_id: akkuwarnung_echt
```

Defaults: channel 1, address `0x40`, shunt `0.1 ohm` (R100), SDA on XIAO D4/GPIO22, SCL on D5/GPIO23, five-second readings. Channels 2 and 3 are unused. Actual address and shunt value must be checked on the delivered board.

The physical prototype was wired with **SDA on D5/GPIO23 and SCL on D4/GPIO22** instead. To use this arrangement without resoldering, add these two entries to the package's `vars` mapping:

```yaml
      pm_sda_pin: GPIO23
      pm_scl_pin: GPIO22
```

Choose the arrangement matching your actual wires; the earlier diagram shows the default arrangement.

On 2026-10-06 the prototype reported 3.25 V at the module's VS/GND pins. After encrypted OTA with SDA on GPIO23 and SCL on GPIO22, the I2C scan found address `0x40`. Connection interruptions still need investigation before battery readings and charge detection can be declared verified.

With USB connected, the first live readings were approximately 3.71 V battery voltage and −0.114 A battery current; Home Assistant displayed **Charging** and **USB**. This confirms initial charging measurements with USB power. Battery-only connection interruptions, discharge measurements and runtime calibration remain to be checked.

The firmware can be preloaded without the module. Contact detection and USB source detection continue; battery voltage, current, charging and runtime remain unknown. Restart the ESP after installing the module because the standard ESPHome driver initializes it at startup. Lost readings expire after 20 seconds, checked every five seconds.

## Verify the delivered board before wiring

The seller images disagree: the red wiring diagram bypasses the shunts and connects to a GND label, while the schematic specifies 1-ohm shunts despite R100 markings in the board photo. The schematic also shows a shared POWER connection. Do not use these images as a verified terminal map.

With the module disconnected from USB, the ESP and the battery, identify its ground, shared supply connections and both ends of channel 1's shunt using continuity checks. No exact physical battery terminal assignment has been verified yet. Chip supply VS and I2C pull-ups must use 3.3 V with this ESP. VPU is an output pull-up supply, not a substitute for VS.

The intended measurement path is battery positive → channel 1 shunt → ESP BAT positive, with a common ground. Positive current means discharge and negative current means charge with this orientation. Whether this board exposes that path without modification remains to be checked. Keep the existing BAT pad joints; any inline insertion belongs in the battery lead.

The existing USB divider stays: VBUS → 8.2 kΩ → D3 junction → 12 kΩ → GND. See [power monitoring](POWER-MONITORING.md) for charging thresholds and the manually calibrated, approximate runtime calculation. No runtime or percentage accuracy has been demonstrated on real measurement hardware.

References: [ESPHome INA3221 driver](https://esphome.io/components/sensor/ina3221/), [TI INA3221 datasheet](https://www.ti.com/lit/ds/symlink/ina3221.pdf).
