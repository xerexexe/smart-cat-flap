# INA3221 battery monitoring

[Deutsch](INA3221.de.md)

The prototype now uses an optional INA3221 firmware package for the installed black DAOKAI three-channel module. The earlier INA219 package remains an alternative; **use one measurement package only**.

The firmware was prepared with ESPHome 2026.9.1 through encrypted OTA on 2026-10-05. Module installation, the pin adjustment and the first confirmed charging readings followed on 2026-10-06, as recorded below.

## Firmware

Copy `power-monitoring-ina3221.yaml` and `usb-detection.yaml` beside your device configuration:

```yaml
packages:
  power_monitor: !include power-monitoring-ina3221.yaml
```

The package includes USB detection. Remove any separate `usb_detection` package or inline copy of its entities before adding it. For the existing German firmware, use the same ID overrides as the INA219 package:

```yaml
packages:
  power_monitor: !include
    file: power-monitoring-ina3221.yaml
    vars:
      pm_battery_script: akku_verarbeiten
      pm_voltage_id: akkuspannung_echt
      pm_warning_id: akkuwarnung_echt
```

Defaults: channel 1, address `0x40`, shunt `0.1 ohm` (R100), SDA on XIAO D4/GPIO22, SCL on D5/GPIO23, five-second readings. Channels 2 and 3 are unused. Actual address and shunt value must be checked on the delivered board.

The physical prototype was wired with **SDA on D5/GPIO23 and SCL on D4/GPIO22** instead. To use this arrangement without resoldering, add these two entries to the package's `vars` mapping:

```yaml
      pm_sda_pin: GPIO23
      pm_scl_pin: GPIO22
```

Choose the arrangement matching your actual wires; the earlier diagram shows the default arrangement.

On 2026-10-06 the prototype reported 3.25 V at the module's VS/GND pins. After encrypted OTA with SDA on GPIO23 and SCL on GPIO22, the I2C scan found address `0x40`. The first attempt without USB had connection interruptions.

With USB connected, the first live readings were approximately 3.71 V battery voltage and −0.114 A battery current; Home Assistant displayed **Charging** and **USB**. This confirms initial charging measurements with USB power. Battery-only connection interruptions, discharge measurements and runtime calibration remain to be checked.

During the later display-rounding check, fresh valid readings stopped even with USB connected. The card therefore showed **Unknown** again instead of retaining earlier values. Continuous measurement reliability is not yet confirmed; these interruptions need investigation.

The firmware can be preloaded without the module. Contact detection and USB source detection continue; battery voltage, current, charging and runtime remain unknown. Restart the ESP after installing the module because the standard ESPHome driver initializes it at startup. Lost readings expire after 20 seconds, checked every five seconds.

## Actual prototype wiring · 2026-10-06

| INA3221 | Connection |
|---|---|
| VS | ESP 3V3 |
| GND | ESP GND |
| SDA | ESP D5 / GPIO23 |
| SCL | ESP D4 / GPIO22 |
| VIN1+ | Battery positive |
| VIN1− | ESP BAT+ |

Battery negative remains connected to ESP BAT−. VIN1− is not a ground terminal. VPU, channels 2/3 and alert terminals are unused. Disconnect USB and electrically disconnect the battery before soldering. The two pin overrides above match this wiring.

The automatic dashboard card displays voltage with two decimal places: **3.71 V** in English or **3,71 V** in German. Display rounding does not improve measurement accuracy.

## Checks for other module variants

The seller images disagree: the red wiring diagram bypasses the shunts and connects to a GND label, while the schematic specifies 1-ohm shunts despite R100 markings in the board photo. The schematic also shows a shared POWER connection. Do not use these images as a verified terminal map.

With the module disconnected from USB, the ESP and the battery, identify its ground, shared supply connections and both ends of channel 1's shunt using continuity checks. Use the actual VIN labels and the prototype table above; verify any differently labelled board first. Chip supply VS and I2C pull-ups must use 3.3 V with this ESP. VPU is an output pull-up supply, not a substitute for VS.

The installed measurement path is battery positive → channel 1 shunt → ESP BAT positive, with a common ground. Positive current means discharge and negative current means charge with this orientation. The observed −0.114 A corresponds to about 114 mA charging current. The module sits in the battery lead, allowing the existing BAT pad joints to remain.

The existing USB divider stays: VBUS → 8.2 kΩ → D3 junction → 12 kΩ → GND. See [power monitoring](POWER-MONITORING.md) for charging thresholds and the manually calibrated, approximate runtime calculation. No runtime or percentage accuracy has been demonstrated on real measurement hardware.
